# 网关调度：按集群识别状态过期与容量风险

交付一个可复现的离线分析和候选调度规则。**优先改进健康状态新鲜度检查，并按集群区分容量信号。** 尚未部署或证明线上收益。

## 我的判断

### 先纠正数据口径

来源仅为题目发放的 `data/gateway_requests.csv`，无外部业务数据。文件原样保留，SHA256：

```text
b29c0c4531deafe5921397720cc0518bf50957cebbf965bfc356606c77866620
```

| 检查 | 结果与处理 |
| --- | --- |
| 原始记录 | 1078 行，8 列 |
| 完全重复记录 | 51 行；去重后 1027 次唯一请求，无相同 ID 的冲突记录 |
| 最终结果 | 850 成功、126 失败、51 未知；已知结果失败率为 126 / 976 = **12.91%** |
| 缺失结果 | 按题意为客户端中断未回传，保留为未知，不当作成功或失败 |
| 时间 | 请求时间带 +08:00，状态时间带 Z；统一到 UTC 再相减 |
| 特征完整性 | 路由特征无缺失，时间均可解析，状态年龄非负；槽位、包体非负 |
| 零值 | 47 次槽位为 0、2 次包体为 0，题目没有说是无效值，因此保留 |

请求覆盖北京时间 2026-09-01 07:00 至 2026-09-07 21:50。审计结果见 `outputs/audit.json`。若将 51 个未知结果分别视为全成功、全失败，总体失败率范围为 126 / 1027 = 12.27% 至 177 / 1027 = 17.23%；12.91% 只代表已知结果样本。

### 看到的风险不是同一种

派生特征：`status_age_minutes = (request_time_utc - node_status_synced_at_utc) / 60秒`。槽位是**上次同步时**的快照，并非决策时真实可用容量；状态越旧，快照越不可信。

全量描述中，状态年龄 ≤15 分钟的已知失败率为 **31 / 713 = 4.35%**，>15 分钟为 **95 / 263 = 36.12%**。但集群分层后，差异明显：

| 集群 | 状态 ≤15 分钟：失败/已知 | 状态 >15 分钟：失败/已知 |
| --- | --- | --- |
| 华东边缘集群 | 4/169，2.37% | 30/65，46.15% |
| 华南算力主集群 | 4/183，2.19% | 31/65，47.69% |
| 香港低延迟专线 | 2/177，1.13% | 27/64，42.19% |
| 华北异构集群 | 21/184，11.41% | 7/69，10.14% |

华北更明显的信号是槽位：`available_slots ≤ 3` 时失败 **27/41 = 65.85%**，>3 时 **1/212 = 0.47%**。直接按状态年龄全局熔断会漏掉华北的新鲜低槽位风险，也会误标华北旧状态但容量充足的目标。

**根问题判断：网关可能没有充分区分“健康快照过期”和“容量不足”，也没有按集群校准风险。** 这是数据支持的工程假设，不是已证实的因果根因；还需排查同步链路、节点日志和调度实现。数据没有节点 ID，不能定位具体坏节点或把集群整体判为不可用。

已额外输出模型规格×状态年龄、包体分组，供核查混杂与复杂度差异。本版不据此新增大量条件：一周样本较少，优先保留可解释、可验证的主要信号。

## 做了什么

1. 在 `main.py` 完成校验、去重、UTC 时间对齐、特征计算、分层分析和逐请求回放。
2. 按时间排序，前约 70% 为规则选择集 **717 次**，后段为时间验证集 **310 次**；切分点为北京时间 **2026-09-05 21:09**。同一时间戳不跨集合。
3. **只在前段**搜索 48 组粗粒度阈值：年龄 `[5,10,15,20,30,45,60,不用]` 分钟，槽位 `[不用,0,1,2,3,5]`。以 `120×覆盖的已知失败数 − 10×标记请求数` 最大化选出共享阈值 **15 分钟、3 个槽位**；并列时优先更少标记。
4. 在同一前段，为每个集群从“不干预 / 仅年龄 / 仅槽位 / 两者 OR”四种方式中选择，固定阈值，不逐集群继续微调。随后冻结规则，在后段回放。
5. 输出 `policy.json`、规则比较、逐请求标记、成本敏感性及测试。`predict_flags` 不读取 success；success 只参与历史规则选择和评估。

生成的候选规则：

| 目标集群 | 标记该请求的目标暂不可用 / 要求刷新或改派的条件 |
| --- | --- |
| 华东边缘集群、华南算力主集群、香港低延迟专线 | 状态年龄 **>15 分钟** |
| 华北异构集群 | 剩余槽位 **≤3** |
| 未见过的集群 | 暂按全局 `年龄>15 或 槽位≤3` 回退，需单独校准 |

这不是“丢弃请求”或“禁用整个集群”的策略。建议在具备可用替代节点时绕开目标；状态过期可先主动刷新健康状态，刷新失败再隔离目标。实际集成还需节点 ID、同模型规格的候选容量、限次重试和幂等保障。华北无需因本样本中的年龄相关性弱而取消基础心跳、探活和硬性健康检查。

当前数据年龄主要分布在 0–13 与 17–65 分钟，14–16 分钟无样本；15 分钟是粗网格中的候选边界，不能证明它是生产环境的精确最优 TTL。

## 怎么证明有用

### 后段时间回放

后段 310 次请求：261 成功、36 失败、13 未知；不干预的**已知失败损失**为 `36×120 = 4320 元`。

| 策略 | 标记请求数 | 覆盖的已知失败 | 被标记的原成功 | 被标记的未知 | 乐观情景总成本/元 | 相对不干预净收益/元 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 不干预 | 0 | 0 | 0 | 0 | 4320 | 0 |
| 全部标记 | 310 | 36 | 261 | 13 | 3100 | 1220 |
| 仅年龄 >15 | 85 | 31 | 50 | 4 | 1450 | 2870 |
| 仅槽位 ≤3 | 47 | 12 | 33 | 2 | 3350 | 970 |
| 全局 OR | 116 | 34 | 76 | 6 | 1400 | 2920 |
| **分集群规则** | **79** | **34** | **41** | **4** | **1030** | **3290** |

分集群规则标记 **79/310 = 25.48%** 的请求，覆盖已知失败 **34/36 = 94.44%**；已知结果中的标记精确率 **34/(34+41) = 45.33%**。41 个原成功请求也会被干预，不能把所有命中都称为坏节点。

相比全局 OR，覆盖同样 34 次已知失败，少标记 **37 次**，该成本代理下少花 **370 元**。这是本版比单纯提高失败召回更有价值的部分。

全量描述性回放：标记 **252/1027** 次，覆盖 **115/126** 次已知失败，另标记 120 次原成功和 17 次未知；乐观净收益为 **11280 元**。全量包含规则选择数据，不当作独立验证结果。

### 成本假设与敏感性

题目是“提前标记节点不可用一次 10 元”，但没有节点 ID、状态事件或恢复时间，无法计算真实事件次数。本版以**每个标记请求收取 10 元**作为可审计代理；若同一事件影响多次请求，这可能高估事件费用，但未知的刷新、改派、容量和等待费用未包含，故不宣称它是实际总成本的上下界。

上表乐观情景假设：标记到的失败全部可挽回，原成功不被破坏，即 `q=100%, r=0%`；并对未知请求收取动作费但不计额外收益。成本为 `未覆盖的已知失败×120 + 所有标记×10`。**不是线上已经节省 3290 元。**

令 q 为原会失败请求被改派挽回的比例，r 为原会成功请求因干预新增失败的比例，固定规则后的已知结果净收益为：

```text
净收益 = 120 × (q × 覆盖的已知失败 − r × 被标记的原成功) − 10 × 所有标记
后段   = 120 × (34q − 41r) − 790
```

| 后段假设（非观测结果） | 净收益/元 |
| --- | ---: |
| q=0%，r=0% | -790 |
| q=25%，r=0% | 230 |
| q=50%，r=0% | 1250 |
| q=50%，r=5% | 1004 |
| q=100%，r=0% | 3290 |

在 r=0、此动作费代理下，至少需要挽回 `790/(34×120) = 19.36%` 的命中失败才能回本；若 r>0，要求更高。未知结果不参与精确率、召回率分母；`sensitivity.csv` 另给出把被标记未知全当原成功、全当原失败的情景端点。q=100%、r=0 时，后段两个端点为 3290 与 3770 元，差额 4×120；不能凭这些未知值判定客户端中断原因。

### 证据边界与后续验证

- 时间回放仍是观察性评估：全量探索先于规则设计，后段并非从未查看的盲测集。脚本的阈值和集群模式选择只读取前段，仍需用新增日期数据确认稳定性。
- 只有一周、后段 36 次已知失败，集群分层样本更少；阈值可能过拟合，相关性不能排除负载、同步实现和模型规格等混杂。
- 没有延迟、超时阈值、节点 ID、改派结果，不能计算等待节省、节点级误报率或真正的端到端成功率。槽位为旧快照，线上需实时校验。
- 先影子运行记录标记原因，再按同一模型规格小流量对照；观测端到端失败率、超时率、p95/p99 等待、恢复请求比例 q、误干预新增失败 r、实际不可用事件数与动作费。保留随机对照，避免只观察被放行请求。
- 对照结果为负、尾延迟恶化或替代容量不足时回滚；隔离目标应有探活和恢复机制，避免长期误封或把流量压垮其他节点。本版没有执行线上操作。

## 复现

需要 Python 3.13 与 uv；依赖仅 pandas、pytest 及其传递依赖，版本由 `uv.lock` 固定。不需要数据库、Notebook、API Key 或外部服务。

```powershell
uv sync --locked
uv run --locked python main.py
uv run --locked pytest -q
```

可指定路径：

```powershell
uv run --locked python main.py --input data/gateway_requests.csv --output-dir outputs
```

脚本只读取源文件，覆盖生成指定输出目录中的同名分析文件。结果清单：

| 输出 | 对应证据 |
| --- | --- |
| `outputs/audit.json` | 文件 SHA256、去重、标签、日期和切分审计 |
| `outputs/cluster_age_groups.csv`、`cluster_slot_groups.csv`、`cluster_cross_groups.csv` | 集群与两类信号的分层计数、已知分母、未知计数 |
| `outputs/age_groups.csv`、`model_age_groups.csv`、`payload_groups.csv` | 补充描述性分析 |
| `outputs/training_candidates.csv` | 仅前段的 48 组阈值比较 |
| `outputs/policy.json` | 冻结的候选规则与切分点 |
| `outputs/policy_comparison.csv` | 前段、后段、全量的规则回放，README 表格数字来源 |
| `outputs/request_decisions.csv` | 每个唯一请求的分段、特征、规则模式与标记，支持逐条核查 |
| `outputs/sensitivity.csv` | 固定规则后的 q/r 和未知结果情景 |

测试覆盖时区对齐、阈值边界、重复/冲突 ID、异常输入、缺失标签、成本计算、同时间戳切分和不依赖 success 的判定。测试夹具为明确标记的合成边界数据，**不用于以上业务结论**。真实 CSV 通过脚本回放验证。

本地验证：**13 项测试通过**；其中真实文件集成测试使用标准库 CSV / datetime 独立重算后段标记和成本，核对 79 次标记、34 次已知失败命中及 3290 元乐观情景净收益。另核对源文件哈希、逐请求唯一性、缺失标签保留及分段计数一致性。
